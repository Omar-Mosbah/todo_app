4. نموذج المهمة: درس في OOP · The Task model as an OOP lesson

هذا هو الملف lib/models/task.dart كاملًا كما هو في مشروعك. سنشرحه جزءًا جزءًا. (Your real file, explained piece by piece.)

class Task {                                   // ① the class (blueprint)
  final String taskName;                       // ② fields
  final String taskDescription;
  final bool isHighPriority;
  bool isDone = false;                         //    not final: it changes

  Task({                                       // ③ constructor
    required this.taskName,
    required this.taskDescription,
    required this.isHighPriority,
    this.isDone = false,
  });

  Map<String, dynamic> toJson() => {          // ④ method: object → Map
    'taskName': taskName,
    'taskDescription': taskDescription,
    'isHighPriority': isHighPriority,
    'isDone' : isDone,
  };

  factory Task.fromJson(Map<String, dynamic> json) {  // ⑤ factory: Map → object
    return Task(
      taskName: json["taskName"],
      taskDescription: json["taskDescription"],
      isHighPriority: json["isHighPriority"],
      isDone: json["isDone"] ?? false          // ⑥ old tasks had no isDone
    );
  }
}

① الكلاس والكائن · Class vs object

العربية

الكلاس قالب أو تصميم. الكائن (Object) شيء حقيقي مصنوع من هذا القالب.

مثال: استمارة فارغة هي الكلاس، وكل استمارة ملأها شخص هي كائن. القالب واحد، والكائنات كثيرة.

كل كائن له نسخته الخاصة من البيانات. إذا أصبحت t1.isDone تساوي true، تبقى t2.isDone كما هي.

English

A class is a blueprint. An object is a real thing built from it.

Think of a blank form (class) and each filled-in copy (object). One blueprint, many objects.

Each object has its own copy of the data: changing t1.isDone does not touch t2.

Task t1 = Task(taskName: "Study", taskDescription: "", isHighPriority: true);
Task t2 = Task(taskName: "Gym",   taskDescription: "", isHighPriority: false);

العربية

الفكرة: عندما تمنع تغيير ما لا يجب أن يتغير، يحميك المترجم (compiler) من الأخطاء قبل أن يعمل التطبيق.

و isDone = false تعني قيمة افتراضية: كل مهمة جديدة تبدأ غير منجزة.

English

The idea: lock what shouldn't change, and the compiler catches mistakes before the app runs.

isDone = false is a default value: every new task starts not done.

③ المُنشئ · The constructor

العربية

المُنشئ (Constructor) هو ما يعمل عندما تكتب Task(...). وظيفته أن يملأ الحقول.

  • الأقواس { } تعني معاملات مسمّاة (named parameters)، فتكتب اسم كل معامل عند الاستدعاء: Task(taskName: "...").
  • required تعني أن المعامل إجباري، وإلا لن يُترجَم الكود.
  • this.taskName اختصار معناه: «خذ القيمة القادمة وضعها في الحقل taskName».
English

The constructor runs when you write Task(...). Its job: fill the fields.

  • { } = named parameters: you write each name when calling.
  • required = must be passed, or the code won't compile.
  • this.taskName = "put the incoming value into the field taskName".

④ الدالة toJson() · A method: object → Map

العربية

الدالة (Method) هي function تعيش داخل الكلاس وتعمل على بيانات الكائن نفسه.

لماذا نحتاجها؟ SharedPreferences لا يعرف ما هو Task. هو يفهم النصوص فقط. لذلك نحوّل الكائن إلى Map، ثم يحوّل jsonEncode الـ Map إلى نص.

  • => اختصار لـ { return ...; } عندما تكون الدالة سطرًا واحدًا.
  • Map<String, dynamic>: المفاتيح كلها نصوص، والقيم من أي نوع (String أو bool)، لذلك نكتب dynamic.
English

A method is a function that lives inside the class and works on that object's data.

Why? SharedPreferences doesn't know what a Task is — only text. So: object → Map → jsonEncode → String.

  • => is shorthand for { return ...; }.
  • Map<String, dynamic>: keys are strings, values can be any type.

⑤ ما هو factory constructor؟ · What is a factory constructor?

العربية

المُنشئ العادي عندما تكتب Task(...) يفعل ثلاثة أشياء تلقائيًا:

  1. يحجز مكانًا في الذاكرة لكائن جديد.
  2. يملأ الحقول بالقيم.
  3. يعيد هذا الكائن.

ولا تتحكم أنت في هذه الخطوات: لا تستطيع كتابة return، ولا إعادة كائن قديم.

كلمة factory تقول لـ Dart: «لا تصنع كائنًا وحدك، أنا سأقرّر ماذا أعيد». فهي في الحقيقة function عادية، لكن شكلها من الخارج يشبه المُنشئ.

English

A normal constructor does three things automatically: reserve memory for a new object, fill the fields, return it. You can't write return or hand back an old object.

The word factory tells Dart: "don't create an object yourself — I'll decide what to return." It's really a plain function that looks like a constructor from the outside.

تشبيه 🍔: المُنشئ العادي مثل آلة: تضع المكونات فيخرج ساندويتش جديد دائمًا. أما factory فمثل الكاشير: تطلب ساندويتش، وهو يقرّر: يصنعه من جديد، أو يعطيك واحدًا جاهزًا. أنت في النهاية تستلم ساندويتش.

Analogy: a normal constructor is a machine — always a fresh sandwich. A factory is a cashier — they decide whether to make one or hand you a ready one.

المُنشئ العاديfactoryNormal vs factory
يصنع كائنًا جديدًا تلقائيًا؟✅ دائمًا❌ أنت تصنعهAuto-creates a new object?
يمكن كتابة return؟❌✅ وإجباريCan use return?
يمكن إعادة كائن موجود سابقًا؟❌✅Can return an existing object?
يمكن استخدام this داخله؟✅❌ لا يوجد كائن بعدCan use this?
العربية

لماذا لا يوجد this داخل factory؟

داخل المُنشئ العادي يكون الكائن قد صُنع وأنت تملؤه، فـ this يشير إليه. أما داخل factory فلا يوجد كائن بعد. لذلك داخل fromJson نستدعي Task(...) العادي ليصنع الكائن فعلًا.

أي أن factory لا يبني: هو يجهّز البيانات ويعطيها للمُنشئ العادي الذي يبني.

Task.fromJson: مُنشئ له اسم

لا تسمح Dart بمُنشئين لهما الاسم نفسه، لذلك نعطي المُنشئ الثاني اسمًا بعد النقطة: Task.fromJson. هذا اسمه named constructor.

English

Why no this inside a factory?

In a normal constructor the object already exists while you fill it. In a factory there's no object yet — so fromJson calls the normal Task(...) to actually build it.

The factory doesn't build; it prepares the data and hands it to the real constructor.

Task.fromJson: a named constructor

Dart doesn't allow two constructors with the same name, so the second one gets a name after the dot.

أمثلة تبيّن قوة factory · What a factory can do

// (a) Run logic BEFORE creating — validation
factory Task.fromJson(Map<String, dynamic> json) {
  final name = (json["taskName"] as String?)?.trim() ?? "";
  if (name.isEmpty) throw FormatException("Task without a name!");
  return Task(taskName: name, ...);
}

// (b) Return the SAME object every time — singleton
class AppSettings {
  static final AppSettings _instance = AppSettings._internal();
  AppSettings._internal();                 // private real constructor
  factory AppSettings() => _instance;      // always the same object
}
identical(AppSettings(), AppSettings());   // true
العربية

المثال (ب) مستحيل بمُنشئ عادي، لأن العادي يصنع كائنًا جديدًا في كل مرة.

هل يجب أن تكون fromJson من نوع factory؟ لا. كان يمكن كتابتها مُنشئًا عاديًا مع initializer list:

English

Example (b) is impossible with a normal constructor — it always makes a new object.

Must fromJson be a factory? No. A normal named constructor with an initializer list also works:

Task.fromJson(Map<String, dynamic> json)
    : taskName = json["taskName"],
      taskDescription = json["taskDescription"],
      isHighPriority = json["isHighPriority"],
      isDone = json["isDone"] ?? false;
العربية

لكن المبرمجين يفضّلون factory لـ fromJson لثلاثة أسباب: المرونة (يمكن إضافة تحقق أو if لاحقًا)، والوضوح (جسم عادي مع return)، والعُرف (هكذا يكتبها مجتمع Flutter).

English

People still prefer factory for fromJson: flexibility (add checks later), clarity (a normal body with return), and convention.

⑥ السطر ?? false · The ?? false line

العربية

العامل ?? يعني: «إن كانت القيمة على اليسار null، فاستخدم القيمة على اليمين».

لماذا هنا؟ المهام القديمة حُفظت قبل أن تضيف الحقل isDone، فلا يوجد فيها هذا المفتاح أصلًا. بدون ?? تصبح القيمة null، والنوع bool لا يقبل null، فيتوقف التطبيق.

هذا السطر يجعل الكود متوافقًا مع البيانات القديمة (backward compatible).

English

?? means "if the left side is null, use the right side".

Why here? Tasks saved before isDone existed don't have that key. Without ?? you'd pass null into a bool → crash.

This line keeps old data working with new code: backward compatible.

الخلاصة — مبادئ OOP في هذا الكلاس: التغليف (Encapsulation): البيانات وطرق تحويلها في مكان واحد، والكلاس هو الذي «يعرف» كيف يحوّل نفسه. عدم القابلية للتغيير (Immutability): final على ما لا يتغير. مسؤولية واحدة: الكلاس يمثّل مهمة فقط.

OOP takeaways: encapsulation (data + its conversions together), immutability (final), single responsibility (it only represents a task).

5. دورة الحفظ والقراءة · The save / load cycle

SAVE:  Task ──toJson()──▶ Map ──list.add──▶ List<Map> ──jsonEncode──▶ String ──setString("tasks")──▶ disk

LOAD:  disk ──getString("tasks")──▶ String ──jsonDecode──▶ List<dynamic> ──map(Task.fromJson)──▶ List<Task>
العربية

هذه أهم فكرة في المشروع كله. عند إضافة مهمة في add_task.dart:

  1. نقرأ النص المحفوظ القديم.
  2. نحوّله إلى قائمة بواسطة jsonDecode.
  3. نضيف المهمة الجديدة بصيغة Map.
  4. نحوّل القائمة كلها إلى نص بواسطة jsonEncode ونحفظها.

قاعدة مهمة: نحن نحفظ القائمة الكاملة في كل مرة. إذا حفظنا جزءًا من القائمة فقط، تضيع بقية المهام. تذكّر هذه القاعدة، لأنك ستحتاجها في قسم المشكلات.

ملاحظة: jsonEncode(taskMapped) يعمل مباشرة على List<Task> لأن jsonEncode يستدعي toJson() تلقائيًا على كل كائن.

English

This is the single most important idea in the project. When adding a task in add_task.dart:

  1. Read the old saved string.
  2. Turn it into a list with jsonDecode.
  3. Add the new task as a Map.
  4. jsonEncode the whole list back to a string and save it.

Key rule: you always save the whole list. Save only part of it and the other tasks are gone. Keep this rule in mind — the bugs section depends on it.

Note: jsonEncode(taskMapped) works directly on a List<Task> because jsonEncode calls each object's toJson() automatically.

6. StatelessWidget و StatefulWidget · Widgets and state

ما معنى الحالة (State)؟ · What is state?

العربية

الحالة هي أي بيانات قد تتغير والشاشة معروضة، فتحتاج الشاشة أن تتحدث عندما تتغير. أمثلة من مشروعك:

  • مربع الاختيار للمهمة (isDone) ← حالة.
  • التبويب المختار في BottomNavigationBar (_currentIndex) ← حالة.
  • مفتاح الأولوية Switch في شاشة الإضافة ← حالة.
  • عنوان ثابت مثل "My Tasks" ← ليس حالة.
English

State is any data that can change while the screen is showing, so the screen must redraw. From your project:

  • A task's checkbox (isDone) → state.
  • The selected tab (_currentIndex) → state.
  • The priority Switch → state.
  • A fixed title like "My Tasks" → not state.

تشبيه 📺: Stateless مثل صورة مطبوعة: لتغييرها تطبع صورة جديدة (أي يرسل الأب بيانات جديدة). Stateful مثل شاشة تلفزيون: الجهاز ثابت، لكن ما يُعرض عليه يتغير.

Analogy: Stateless = a printed photo (reprint to change it). Stateful = a TV (same device, changing picture).

StatelessWidget: الكود الجاهز سطرًا سطرًا · The boilerplate, line by line

class TaskTitle extends StatelessWidget {          // 1
  const TaskTitle({super.key, required this.title}); // 2

  final String title;                               // 3

  @override                                         // 4
  Widget build(BuildContext context) {              // 5
    return Text(title);
  }
}
العربية
  1. extends تعني الوراثة (Inheritance): كلاسك يرث كل شيء من StatelessWidget، فيعرف Flutter أنه widget.
  2. المُنشئ:
    • const: يمكن صنع الكائن مرة واحدة وقت الترجمة، فلا يعيد Flutter بناءه بلا داعٍ. أداء أفضل. وشرطه أن تكون كل الحقول final.
    • super.key: الـ key مثل بطاقة هوية للـ widget (مهم في القوائم). و super تعني «أرسله إلى الكلاس الأب»، لأن الأب هو من يملك هذا الحقل.
  3. البيانات القادمة من الخارج. يجب أن تكون final، لأن الـ widget في Flutter لا يتغير بعد صنعه. للتغيير يصنع Flutter widget جديدًا.
  4. @override: «أكتب نسختي الخاصة من دالة موجودة في الأب». ويتأكد المترجم أنك كتبت الاسم صحيحًا.
  5. build أهم دالة في Flutter: تعيد شكل الـ widget. و BuildContext context هو مكان هذا الـ widget في الشجرة، ومنه تصل إلى ما فوقه، مثل Theme.of(context) و Navigator.of(context).
English
  1. extends = inheritance: you inherit everything from StatelessWidget.
  2. Constructor: const lets Flutter skip needless rebuilds (all fields must be final). super.key passes the widget's ID card up to the parent class, which owns that field.
  3. Data from outside — must be final: widgets are immutable; to change, Flutter makes a new one.
  4. @override: "my own version of a parent method"; the compiler checks the name.
  5. build returns what the widget looks like. context is its position in the tree, used for Theme.of, Navigator.of, …

class MainScreen extends StatefulWidget {          // A: the widget
  const MainScreen({super.key});

  @override
  State<MainScreen> createState() => _MainScreenState();   // B: the link
}

  Widget build(BuildContext context) {
    return Scaffold(

        onTap: (int? index) {

            _currentIndex = index ?? 0;
          });
        },
        ...
      ),
      body: Screens[_currentIndex],
    );
  }
}
العربية

لماذا كلاسان؟ 🤔

هذا أكثر سؤال يربك المبتدئين:

  • (A) MainScreen هو الـ widget، وهو لا يتغير مثل أي widget. Flutter يرميه ويصنع غيره كثيرًا.
  • (C) _MainScreenState هو الذي يحمل البيانات المتغيرة، وهو يبقى حيًّا حتى لو صُنع الـ widget من جديد.

تشبيه: الـ widget مثل بطاقتك الشخصية، قد تُطبع منها نسخ جديدة كثيرة. والـ State هو أنت: تبقى الشخص نفسه وذكرياتك معك مهما طُبعت البطاقة.

English

Why two classes?

  • (A) the widget is immutable; Flutter throws it away and recreates it often.
  • (C) the State holds the changing data and survives those recreations.

Analogy: the widget is your ID card (reprinted many times); the State is you — same person, same memories.

العربية
  • (B) createState(): الوصلة بين الكلاسين. يستدعيها Flutter مرة واحدة عند ظهور الـ widget أول مرة، ليصنع كائن الـ State ويحتفظ به.

  • _ = private to the file. Nobody outside needs the State — encapsulation.

  • (D) setState: "data changed — re-run build".

دورة الحياة · Lifecycle

createState() ──▶ initState() ──▶ build() ◀──▶ setState() re-runs build()
                                       │
                                       ▼
                                   dispose()   ← widget removed from screen
@override

  super.initState();      // call the parent FIRST
  _loadTasks();
}

@override
void dispose() {
  _controller.dispose();
  super.dispose();        // call the parent LAST
}
العربية
  • initState(): مرة واحدة في البداية. مكان تحميل البيانات.
  • dispose(): مرة واحدة في النهاية. مكان التنظيف، مثل إغلاق TextEditingController.

كيف تختار؟ اسأل: «هل يحتاج هذا الـ widget أن يغيّر شكله بنفسه بعد رسمه؟» لا ← Stateless (ابدأ به دائمًا، فهو أبسط). نعم ← Stateful.

💡 في VS Code اكتب stless أو stful واضغط Enter ليُكتب الكود الجاهز. ويمكن التحويل بينهما بـ Ctrl + . على اسم الكلاس.

English
  • initState(): once at the start — load data here.
  • dispose(): once at the end — clean up (e.g. controllers).

Which one? "Does this widget need to change itself after it's drawn?" No → Stateless (start here). Yes → Stateful.

Tip: type stless / stful in VS Code; convert with Ctrl + . on the class name.

⑤ validator · The grading rule

العربية

دالة تستقبل النص المكتوب value وتعيد واحدًا من شيئين:

  • نص ← يوجد خطأ، وFlutter يعرض هذا النص بالأحمر تحت الحقل.
  • null ← الإدخال صحيح، لا يوجد خطأ.

لذلك نوعها String?. انتبه: null هنا تعني «نجح»، وليس «فشل».

لماذا .trim()؟ تحذف المسافات من البداية والنهاية. بدونها يستطيع المستخدم كتابة مسافات فقط " " فيُقبل الاسم.

في ملفك كتبت الـ validator بطريقتين:

  • للاسم: سطر واحد بـ => و ? :.
  • للوصف: جسم كامل مع if. عندما ينجح لا يوجد return، فتعيد Dart null تلقائيًا. هذا يعمل، لكن الأوضح أن تكتب return null; في النهاية، وسيختفي التحذير من المحرر.
English

A function that takes the typed value and returns either:

  • a String → error; Flutter shows it in red under the field.
  • null → valid.

So its type is String?. Careful: here null means "passed".

.trim() removes leading/trailing spaces, so " " doesn't count as a name.

Your file uses two styles: a one-line => with ? : for the name, and a block with if for the description. The block has no return on success, so Dart returns null implicitly — it works, but add return null; to be explicit and silence the editor warning.

  if (value == null || value.trim().isEmpty) {
    return "Task description is required";

},

ماذا تفعل validate() بالضبط؟

  1. تمرّ على كل TextFormField داخل الـ Form.
  2. تشغّل الـ validator الخاص بكل حقل.
  3. تعرض رسالة الخطأ تحت كل حقل فاشل.
  4. تعيد true إذا نجحت كل الحقول، و false إذا فشل حقل واحد على الأقل.

لماذا نحتاج ?? false؟

الشرط if في Dart يقبل bool فقط، ولا يقبل bool?. لأن ?. قد تعطي null، نحتاج ?? لنحوّلها إلى bool مؤكد. واخترنا false لأن الآمن هو: «إن لم أتأكد أن النموذج صحيح، فلا أحفظ».

English

What does validate() do?

  1. Visits every TextFormField in the Form.
  2. Runs each field's validator.
  3. Shows the error text under each failing field.
  4. Returns true if all passed, false if any failed.

Why ?? false?

Dart's if accepts bool, not bool?. Since ?. can produce null, ?? turns it into a definite bool. false is the safe choice: "not sure it's valid → don't save".

// The same line, written the long way:
final FormState? form = _key.currentState;
bool isValid;
if (form == null) {
  isValid = false;           // no form on screen → treat as invalid
} else {
  isValid = form.validate(); // run every validator
}
if (isValid) { /* create Task and save */ }

// Another way you'll see often (uses ! = "I promise it's not null"):
if (_key.currentState!.validate()) { ... }   // crashes if currentState is null
