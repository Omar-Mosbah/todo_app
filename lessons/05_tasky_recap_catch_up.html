3. ماذا يحدث عند تشغيل التطبيق؟ · What happens at startup

void main() async {
  WidgetsFlutterBinding.ensureInitialized();          // 1
  final pref = await SharedPreferences.getInstance(); // 2
  String? username = pref.getString('username');      // 3
  runApp(MyApp(name: username));                      // 4
}
// inside MyApp.build:
home: name == null ? WelcomeScreen() : MainScreen(),  // 5
العربية
  1. ensureInitialized(): نحتاجه لأننا نستخدم await قبل runApp. هو يجهّز Flutter للتواصل مع النظام.
  2. نحصل على نسخة من SharedPreferences (تخزين بسيط على الجهاز بصيغة مفتاح وقيمة).
  3. نقرأ الاسم. النوع String? يعني أن القيمة قد تكون null.
  4. نشغّل التطبيق ونمرّر الاسم.
  5. إذا لم يوجد اسم، فالمستخدم جديد، فنعرض شاشة الترحيب. وإلا نعرض الشاشة الرئيسية.
English
  1. ensureInitialized() is required because we await before runApp. It prepares Flutter to talk to the platform.
  2. Get the SharedPreferences instance (simple key–value storage on the device).
  3. Read the name. String? means it may be null.
  4. Start the app, passing the name in.
  5. No name → new user → WelcomeScreen. Otherwise → MainScreen.

4. نموذج المهمة و JSON · The Task model and JSON

class Task {
  final String taskName;
  final String taskDescription;
  final bool isHighPriority;
  bool isDone = false;            // not final: it changes when you tick the box

  Map<String, dynamic> toJson() => {          // object → Map
    'taskName': taskName, 'taskDescription': taskDescription,
    'isHighPriority': isHighPriority, 'isDone': isDone,
  };

  factory Task.fromJson(Map<String, dynamic> json) {  // Map → object
    return Task(
      taskName: json["taskName"], ...,
      isDone: json["isDone"] ?? false,     // old saved tasks had no isDone
    );
  }
}
العربية

SharedPreferences لا يحفظ كائنات Task مباشرة. هو يحفظ نصًا String فقط. لذلك نحتاج إلى تحويل في الاتجاهين:

  • toJson(): يحوّل الكائن إلى Map.
  • Task.fromJson(): يبني كائنًا من Map. هو factory constructor (مُنشئ يعيد كائنًا جاهزًا)، وقد شرحناه في الدرس 02.

لماذا ?? false؟ لأن المهام القديمة حُفظت قبل إضافة الحقل isDone، فقيمته فيها null. العامل ?? يعني: «إن كانت القيمة null فاستخدم البديل».

English

SharedPreferences cannot store a Task object — only a String. So we convert both ways:

  • toJson(): object → Map.
  • Task.fromJson(): Map → object. It's a factory constructor (covered in lesson 02).

Why ?? false? Tasks saved before you added isDone don't have that key, so it reads as null. ?? means "if null, use this fallback".

5. دورة الحفظ والقراءة · The save / load cycle

SAVE:  Task ──toJson()──▶ Map ──list.add──▶ List<Map> ──jsonEncode──▶ String ──setString("tasks")──▶ disk

LOAD:  disk ──getString("tasks")──▶ String ──jsonDecode──▶ List<dynamic> ──map(Task.fromJson)──▶ List<Task>
العربية

هذه أهم فكرة في المشروع كله. عند إضافة مهمة في add_task.dart:

  1. نقرأ النص المحفوظ القديم.
  2. نحوّله إلى قائمة بواسطة jsonDecode.
  3. نضيف المهمة الجديدة بصيغة Map.
  4. نحوّل القائمة كلها إلى نص بواسطة jsonEncode ونحفظها.

قاعدة مهمة: نحن نحفظ القائمة الكاملة في كل مرة. إذا حفظنا جزءًا من القائمة فقط، تضيع بقية المهام. تذكّر هذه القاعدة، لأنك ستحتاجها في قسم المشكلات.

ملاحظة: jsonEncode(taskMapped) يعمل مباشرة على List<Task> لأن jsonEncode يستدعي toJson() تلقائيًا على كل كائن.

English

This is the single most important idea in the project. When adding a task in add_task.dart:

  1. Read the old saved string.
  2. Turn it into a list with jsonDecode.
  3. Add the new task as a Map.
  4. jsonEncode the whole list back to a string and save it.

Key rule: you always save the whole list. Save only part of it and the other tasks are gone. Keep this rule in mind — the bugs section depends on it.

Note: jsonEncode(taskMapped) works directly on a List<Task> because jsonEncode calls each object's toJson() automatically.

6. الحالة وإعادة الرسم · State and rebuilding

العربية

كل شاشة قائمة هي StatefulWidget، والنمط فيها واحد:

  1. initState() يعمل مرة واحدة عند فتح الشاشة، ويستدعي _loadTasks().
  2. _loadTasks() دالة async، فهي تنتظر القراءة من التخزين.
  3. بعد وصول البيانات نستدعي setState()، فيعيد Flutter تشغيل build() ويعرض القائمة.

عند الضغط على مربع الاختيار Checkbox نفعل شيئين: نغيّر isDone داخل setState لتتحدث الواجهة فورًا، ثم نحفظ في التخزين ليبقى التغيير بعد إغلاق التطبيق.

التفاصيل الكاملة موجودة في الدرس 04.

English

Every list screen is a StatefulWidget with the same pattern:

  1. initState() runs once when the screen opens and calls _loadTasks().
  2. _loadTasks() is async: it waits for storage.
  3. When data arrives, setState() makes Flutter re-run build() and show the list.

Ticking a Checkbox does two things: change isDone inside setState so the UI updates now, then save to storage so the change survives an app restart.

Full details are in lesson 04.

7. النماذج والتحقق من الإدخال · Forms and validation

Form(key: _key, child: ... TextFormField(
  controller: taskNameController,
  validator: (value) => value!.trim().isEmpty ? "Task name is required" : null,
))

if (_key.currentState?.validate() ?? false) { /* save */ }
العربية
  • TextEditingController: يتيح لنا قراءة النص المكتوب (.text) ومسحه (.clear()).
  • validator: يعيد رسالة خطأ إذا كان الإدخال غير صالح، ويعيد null إذا كان صالحًا.
  • GlobalKey<FormState>: مفتاح يربطنا بالنموذج، فنستطيع استدعاء validate() على كل الحقول مرة واحدة.
  • Switch: لاختيار الأولوية العالية، ويُحدَّث بواسطة setState.
English
  • TextEditingController: read the typed text (.text) and clear it (.clear()).
  • validator: return an error message if invalid, null if valid.
  • GlobalKey<FormState>: a handle to the form so you can call validate() on all fields at once.
  • Switch: high-priority toggle, updated with setState.

9. عنصر القائمة المشترك · The shared TasksListWidget

class TasksListWidget extends StatelessWidget {
  final List<Task> task;
  final Function(bool?, int?) onTaskChanged;   // a callback
  ...
  ListView.separated(
    itemCount: task.length,
    separatorBuilder: (context, index) => SizedBox(height: 8),
    itemBuilder: (context, index) => ... Checkbox(
      value: task[index].isDone,
      onChanged: (value) => onTaskChanged(value, index),
    ),
  )
}
العربية

بدل تكرار كود القائمة في ثلاث شاشات، أنشأت عنصرًا واحدًا. لاحظ الفكرة المهمة: العنصر لا يعرف ماذا يفعل عند الضغط. هو فقط يستدعي الدالة onTaskChanged ويعطيها القيمة والرقم index. كل شاشة تقرّر بنفسها ماذا تفعل. هذا اسمه callback (دالة تُمرَّر ليُستدعى بها لاحقًا).

ListView.separated يبني العناصر عند الحاجة فقط، ويضع فاصلًا بين كل عنصرين.

English

Instead of repeating list code in three screens, you made one widget. The key idea: the widget does not know what to do on tap. It just calls onTaskChanged with the value and the index; each screen decides what happens. That's a callback.

ListView.separated builds items lazily and puts a separator between them.

العربية

مشكلة الـ index

في شاشة TodoTasks القائمة مفلترة. الرقم index = 0 فيها قد يكون المهمة الثالثة في القائمة الكاملة. لذلك بدأت آخر مرة تستخدم indexWhere لتجد المكان الصحيح في القائمة الكاملة. هذه هي النقطة التي توقفت عندها بالضبط.

English

The index problem

In TodoTasks the list is filtered. index = 0 there might be the third task in the full list. That's why your last commit uses indexWhere to find the matching position in the full list. This is exactly where you stopped.

10. مشكلات وجدتها في الكود الحالي · Bugs in the current code

هذه ملاحظات من قراءة الكود، ولم أعدّل أي ملف. (From reading the code — no files were changed.)

1. حفظ الجزء بدل الكل — يحذف المهام المنجزة

في todo_tasks.dart السطر 71، بعد أن حدّثت القائمة الكاملة All_data_task، يحفظ الكود القائمة المفلترة taskMapped. النتيجة: كل المهام المنجزة تختفي من التخزين. هذه مخالفة مباشرة للقاعدة في القسم 5.

1. Saving the slice, not the whole — deletes completed tasks

In todo_tasks.dart line 71, after updating the full list All_data_task, the code saves the filtered taskMapped. Result: every completed task is wiped from storage. A direct break of the rule in section 5.

pref.setString("tasks", jsonEncode(taskMapped));     // ✗ current
pref.setString("tasks", jsonEncode(All_data_task));  // ✓ should be
2. فك ترميز نص فارغ — توقف الشاشة

في completed_tasks_screen.dart السطر 25: إذا لم توجد مهام محفوظة، يصبح الاستدعاء jsonDecode("")، وهذا يرمي خطأ FormatException. النص الفارغ ليس JSON صالحًا. استخدم '[]' كما فعلت في todo_tasks.dart.

2. Decoding an empty string — screen crashes

In completed_tasks_screen.dart line 25: with no saved tasks this becomes jsonDecode(""), which throws a FormatException — an empty string isn't valid JSON. Use '[]' as you did in todo_tasks.dart.

3. شاشة الترحيب تفتح الشاشة الخطأ

في welcome_screen.dart السطر 114 ينتقل الكود إلى HomeScreen، وليس إلى MainScreen. لذلك لا يظهر شريط التنقل السفلي للمستخدم الجديد حتى يعيد فتح التطبيق.

3. Welcome screen opens the wrong screen

welcome_screen.dart line 114 navigates to HomeScreen instead of MainScreen, so a new user sees no bottom bar until they restart the app.

4. البحث بالاسم غير آمن

indexWhere يبحث بواسطة taskName. إذا وُجدت مهمتان بالاسم نفسه، فسيحدّث الكود المهمة الأولى دائمًا. وإذا لم يجد المهمة، فيعيد -1 فيتوقف التطبيق. الحل لاحقًا: إضافة id فريد لكل مهمة.

4. Matching by name is fragile

indexWhere matches on taskName. Two tasks with the same name → it always updates the first. Not found → returns -1 → crash. Later fix: give every task a unique id.

5. ملاحظات أصغر
  • في add_task.dart المتحكمات Controllers والمفتاح _key معرّفة خارج الكلاس، فهي متغيرات عامة. الأفضل وضعها داخل _AddTaskState.
  • في todo_tasks.dart يوجد Future.delayed داخل setState. يجب أن يحتوي setState على تغيير البيانات فقط.
  • ينقص @override فوق initState في شاشتين.
5. Smaller notes
  • add_task.dart: the controllers and _key are top-level globals; move them into _AddTaskState.
  • todo_tasks.dart: Future.delayed sits inside setState. Keep setState for data changes only.
  • @override is missing above initState in two screens.
